# Salma MVP Implementation Plan

**Goal:** Implement the supplied refined build plan in this empty workspace.
**Architecture:** Salma owns a separate PostgreSQL/pgvector database, a FastAPI API,
durable worker and React inspection console. Existing Evolution and Chatwoot stay
external; all live outbound messages go through Chatwoot.
**Tech Stack:** Python 3.14, SQLAlchemy, LangGraph, Groq, React/Vite, PostgreSQL 16.
**Spec:** `docs/spec.md` (user-supplied plan).
**Execution:** Inline, explicitly requested by the user on 2026-10-07.

## Global constraints
- No fabricated prices, unauthorized discounts, confirmed bookings or orders.
- Simulator precedes live-channel activation. No live account configuration changes.
- Model ID is configurable; no silent substitution. Customer identity is backend-owned.
- Preserve existing Docker services and use port 5433 for Salma's database.
- Missing original scoring weights and success targets remain unconfigured.

## Review focus
- Duplicate and rapid inbound messages must preserve order and avoid duplicate replies.
- Takeover during generation must suppress the pending response.
- Ambiguous HTTP delivery must not be retried automatically after restart.
- Customer updates and archival must be scoped and explicitly confirmed.
- Arabic/mixed-language retrieval must use compatible embedding partitions.

## Tasks
1. Persistence and adapters: settings, migrations, catalog, authenticated normalization,
   durable deduplication, ownership. Tests: duplicate webhooks, notes, echoes, scope.
2. Agent and trust: typed tools, bounded LangGraph, separate Groq decision, safe rendering,
   handoff and failure handling. Tests: prices, discounts, unsafe arithmetic, evidence.
3. Worker and delivery: per-conversation advisory lock, ordered processing, outbox,
   restart/reconciliation. Tests: takeover and ambiguous sends against PostgreSQL.
4. Simulator and console: authenticated API, history and SSE, React console, ownership.
   Verify API integration tests and production frontend build.
5. Knowledge and launch: PDF extraction/token chunks, separate pgvector partitions,
   bilingual seed, Docker and documentation. Verify fresh Docker startup and migrations.

Each task: write and run failing tests, implement, run suite, record result in progress.md.
